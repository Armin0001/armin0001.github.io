  1. 01 Client work · In production Nov 2025 – Jun 2026

    artifact A-01

    A membership registry for a professional licensing body

    One system for a licensing body’s members, their dues and their paperwork. I designed it, built it and ran it in production, alone.

    The hard part. Access. Ten kinds of records, four things you can do to each, and rules that are policy rather than code. Hard-coding roles would have meant a deploy every time the policy moved.

    Reach
    ~40 member facilities
    Access model
    10 resources × 4 actions
    Team
    Sole developer

    Decisions I’d defend in a review

    Permissions are data, not code

    Every role is a set of create, read, update and delete switches per resource: 10 resources, 4 actions, 40 combinations. Admins change them in a settings screen, so an access change needs no code change and no redeploy.

    The schema follows the real hierarchy

    A legal entity, the licensed individuals registered under it, and each individual’s dues, fees and protocol records. Modelled relationally in PostgreSQL, so the questions the client actually asks are plain joins.

    Documents live with the person they belong to

    Member uploads go to MinIO, S3-compatible object storage, and are tied to the individual’s record rather than floating in a shared folder.

    Outreach became a system, not a chore

    Twilio SMS notifications took over what used to be done by hand. I gathered the requirements straight from a non-technical client, deployed on Vercel with automated deploys from Git, and maintained it in production.

    • PostgreSQL
    • RBAC
    • MinIO / S3
    • Twilio
    • Vercel

  2. 02 Concurrency · Next.js 16

    artifact A-04

    Online Ticket Booth

    Two people click seat J14 in the same instant. Exactly one of them may have it, and the other has to find out immediately.

    The hard part. Selling a seat is a compare-and-set, and anything that slips between the read and the write sells the seat twice. No framework solves that for you. The store has to.

    Venue
    412 seats, 1 streamed string
    Verified by
    45-check browser suite
    Cost of a hold
    2 round trips, down from 5

    Decisions I’d defend in a review

    The one thing I refused to cache

    Availability is only true at the instant you read it, so it is never cached. The same number on the on-sale index is cached for 60 seconds, because being wrong there costs nothing. Same number, two call sites, opposite treatment.

    An order is all or nothing

    SET NX is the right primitive for one seat. An order is up to six. A Lua script reads all six and only then writes, so holding four of the six you asked for is not a state the system can be in.

    One contract, two drivers

    An in-process store and a Redis store are held to the same test contract, and the Redis one was verified against real servers. If Redis is configured but unreachable, the app fails loudly instead of quietly losing the guarantee.

    Only a 412-character string streams

    Seat geometry is pure maths with no I/O, so all 412 seats are prerendered into the static shell in their exact positions. Availability arrives afterwards as one letter per seat.

    • Next.js 16
    • React 19
    • Redis + Lua
    • Partial Prerendering
    • SSE
    • Playwright

  3. 03 Browser extension · Web performance

    artifact A-02

    CO2 Footprint

    One click on any website tells you what a single visit to that page costs, in grams of CO2.

    The hard part. An honest number. A browser won’t tell an extension the size of every file a page loads, and the science behind the conversion is a model, not a meter. So the tool has to be clear about what it measured, what it estimated and what it left out.

    Permissions
    2, used only on click
    Leaves your browser
    Nothing
    Dependencies
    None

    Decisions I’d defend in a review

    Count what a first-time visitor downloads

    The popup reads the page’s own Performance API. Each file is counted once, even when it was preloaded, and cached files count at full size, because the question is what a new visitor pays.

    When the browser won’t say, estimate and say so

    Files from other domains can keep their size private. Those get a typical size for their type, taken from the HTTP Archive Web Almanac, and the popup says how many it estimated. API calls and tracking pings are left out rather than guessed. Chrome also stops recording after 250 files, and when a page hits that, the popup says the real figure is probably higher.

    A published model, not my own maths

    Bytes become grams with the Sustainable Web Design Model v4, using the same constants as CO2.js: 0.3 kWh per gigabyte and 494 g of CO2e per kWh, which comes to about 0.15 g per megabyte. The A+ to F rating uses the model’s own thresholds.

    Private by construction

    It asks for two permissions, activeTab and scripting, so it cannot see a tab until you click it. It makes no network requests and stores nothing. There is no server to send anything to.

    • JavaScript
    • Manifest V3
    • Performance API
    • Zero dependencies

  4. 04 My own project · Live

    artifact A-03

    The Advanced Calculator

    A product on its own domain that I designed, built and have kept shipping since April 2025: 15+ calculators, each one built to be found.

    The hard part. A calculator nobody finds is a calculator nobody uses. The engineering problem here is search visibility: every tool has to be a fast, indexable page with something on it worth ranking.

    Catalogue
    15+ calculators
    Iteration
    39 commits since Apr 2025
    Stack
    Next.js 15, React 19

    Decisions I’d defend in a review

    Every tool is a page with something to index

    Each calculator has its own route, and below the widget sits long-form content that is rendered to HTML on the server: how it works, reference tables, and answers to the questions people actually type. Every tool is a real, indexable document, not an empty shell waiting for JavaScript.

    Structured data from the same source as the page

    One component renders the visible FAQ and emits the matching FAQPage JSON-LD, so what search engines read and what people read cannot drift apart.

    Discovery is automated, not remembered

    The sitemap and robots.txt are regenerated on every build, related-calculator links tie the tools together, and a fuzzy search covers the whole catalogue. Adding a calculator never involves a checklist.

    • Next.js 15
    • React 19
    • Tailwind CSS 4
    • JSON-LD
    • Fuse.js

  5. 05 AI engineering · Evals

    artifact A-05

    Excalidraw AI

    An agent that draws system diagrams from plain English, and a test suite that tells me whether it is getting better or just different.

    The hard part. Model output looks fine until you measure it. Arrows that do not attach, labels that float, boxes that overlap: the failures are structural, so the checks have to be structural too.

    Golden dataset
    30 cases
    Scorers
    8, structural first
    Agent tools
    6, schema-strict

    Decisions I’d defend in a review

    The feedback lives in the tool, not the prompt

    Every call that adds elements returns the pairs that now overlap. The agent sees its own collisions and repairs them before it finishes. Telling a model to avoid overlaps is a wish. Handing it the evidence is a loop.

    What is graded is what runs

    The eval harness imports the same system prompt and the same overlap detector as the deployed agent, and simulates the canvas so it can run without a browser. Every run is an experiment tagged with its commit.

    Malformed tool calls are not representable

    Tool inputs are Zod schemas in strict mode, with nullable fields instead of optional ones, so the model cannot produce a call that fails validation.

    Grounded before it draws

    For domain questions the agent searches a private vector index of reference documents, and the web, before it commits to a diagram. Built while working through Frontend Masters’ AI Engineering Fundamentals.

    • Cloudflare Workers
    • Vercel AI SDK
    • Zod
    • Upstash Vector
    • Braintrust

  6. 06 WebGL · Performance

    artifact A-06

    ÉTHER

    How do you put 26,000 moving particles behind a headline without paying for them in load time?

    The hard part. Heavy visuals usually cost you the first paint, the battery, and everyone who asked for less motion. The page had to be a fast, readable document first and a shader second.

    Particles
    26,000, moved on the GPU
    First paint
    Server-rendered text
    Reduced motion
    A still frame instead

    Decisions I’d defend in a review

    Text first, shader second

    All primary content is server-rendered, so the largest paint is text. Three.js is imported dynamically and never blocks it.

    The motion happens in the vertex shader

    Particles are displaced by layered simplex noise on the GPU, with antialiasing off and the pixel ratio capped at 2. JavaScript only advances a clock.

    It stops when nobody is looking

    The render loop pauses when the canvas scrolls offscreen or the tab is hidden, and every DOM animation sticks to transform and opacity.

    Reduced motion is a designed path

    Visitors who ask for less motion get a still golden frame and the full content, with the scroll effects skipped entirely.

    • Next.js
    • Three.js
    • GLSL
    • GSAP

  7. 07 Interaction design · Motion

    artifact A-07

    Drift

    What if filters came to your cursor instead of living in a sidebar?

    The hard part. A new interaction only works if it stays predictable. Every filter change had to be reversible, explainable in a chip, and reachable without a mouse.

    Catalogue
    60 products, 6 aisles
    Ways in
    Click, flick or keyboard
    Safety net
    Undo on every change

    Decisions I’d defend in a review

    Filters are plain data

    The whole page reflows from one filter object, and every chip carries the function that removes it. That makes undo a function call, not a feature.

    The menu is about what you clicked

    Right-click a product and the ring offers more like this, cheaper than this, or the same colour. Right-click an aisle heading and it offers something else. Hold, flick and release picks a wedge without a second click.

    Taste is derived, not asked for

    “My taste” is built from what you have viewed: the most common vibe, and a price band around the median.

    The browser keeps its rights

    Alt and right-click still opens the normal context menu, every action has a key, and the catalogue is seeded deterministically so server and client always agree.

    • Next.js 16
    • Motion
    • Lenis
    • TypeScript
